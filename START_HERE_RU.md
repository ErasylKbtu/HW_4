**Студент:** Karas Yerassyl

Это планировщик учебных заданий на React. Можно добавить задание, открыть его подробности, изменить поля, отметить выполнение, вернуть задание в работу и удалить его. Данные сохраняются в текущем браузере.

## 1. Как открыть на Windows

1. Распакуй архив. Не запускай проект прямо внутри ZIP.
2. В VS Code выбери **File → Open Folder** и открой папку `homework-effects`.
3. Проверь, что в этой папке виден `package.json`.
4. Открой **Terminal → New Terminal**.
5. Проверь Node.js:

```powershell
node -v
npm -v
```

Подойдёт Node.js 24 LTS; минимальное требование проекта — Node.js 22.12. Если команды не найдены, установи Node.js с https://nodejs.org/ и заново открой VS Code.

6. Выполни по очереди:

```powershell
npm ci
npm run dev
```

7. Открой адрес, который покажет терминал. Обычно это http://127.0.0.1:5173/.

Терминал должен оставаться открытым. Остановить сервер: **Ctrl+C**.

Если PowerShell пишет, что запуск `npm.ps1` запрещён, используй:

```powershell
npm.cmd ci
npm.cmd run dev
```

Двойной щелчок по `index.html` не запускает исходный React-проект. Нужна команда `npm run dev`.

## 2. Как проверить приложение

- **New assignment** — добавить запись.
- Нажатие на карточку — отдельный запрос подробностей.
- **Edit** — изменить поля.
- **Mark as completed** — изменить статус через API.
- **Reopen assignment** — вернуть завершённую запись в статус To do.
- **Remove** — удалить после подтверждения.
- **Reload** — заново запросить список и обновить подробности.

Раскрой **API playground** внизу страницы. Для обычной проверки выбери **Reliable**, чтобы случайная ошибка не прерывала демонстрацию. В **Normal** случайные ошибки включены специально по заданию.

Режим **Slow** позволяет показать задержки и безопасное переключение карточек. Кнопки **Fail next list / details / save** вызывают одну ошибку нужного типа. После ошибки повтори действие — данные и введённый текст сохраняются.

## 3. Как загрузить на GitHub

Создай на GitHub **новый пустой репозиторий**, например `HW_4`. Не добавляй в нём README, лицензию и .gitignore при создании: нужные файлы уже находятся в проекте.

Открой терминал именно в папке `homework-effects`. Затем выполни:

```powershell
git init
git add .
git commit -m "Add React Homework 4: Effects and API"
git branch -M main
```

Скопируй HTTPS-адрес своего нового репозитория. Если твой логин по-прежнему `ErasylKbtu`, а репозиторий называется `HW_4`, следующие команды будут такими:

```powershell
git remote add origin https://github.com/ErasylKbtu/HW_4.git
git push -u origin main
```

Этот адрес является примером для репозитория, который ты создашь. Репозиторий не создан автоматически.

Загружай **весь проект**, а не только `src`. Нужны `package.json`, `package-lock.json`, `index.html`, `vite.config.js`, `.github/workflows/deploy.yml` и остальные исходники. `.gitignore` автоматически исключит `node_modules` и `dist`.

Если появляется предупреждение `LF will be replaced by CRLF`, это предупреждение о переносах строк, а не ошибка загрузки. Если Git требует имя и email автора, настрой их для своего аккаунта и повтори `git commit`.

## 4. Как включить GitHub Pages

1. Открой репозиторий на GitHub.
2. Перейди в **Settings → Pages**.
3. В **Build and deployment → Source** выбери **GitHub Actions**.
4. Открой вкладку **Actions**.
5. Выбери **Deploy StudyFlow to GitHub Pages**.
6. Если первая сборка завершилась ошибкой до включения Pages, нажми **Re-run all jobs**. Также можно запустить **Run workflow** для ветки `main`.
7. Дождись зелёного статуса. Ссылка на сайт появится в результате deployment и в **Settings → Pages**.

Workflow уже добавлен. Он устанавливает зависимости, проверяет Hooks, запускает тесты API, собирает приложение и публикует `dist`. `base: './'` позволяет загружать ресурсы из подпапки репозитория.

Для примера `ErasylKbtu/HW_4` ожидаемый адрес после успешной публикации — `https://ErasylKbtu.github.io/HW_4/`. Это ожидаемый адрес, а не подтверждённая публикация. Проверяй ссылку, выданную GitHub.
